# Botanic 安全运营与恢复

本说明覆盖上线后的安全验收、告警、备份和恢复。普通 UI 测试不调用真实生图服务，也不修改生产数据。

## 1. 上线前权限验收

在隔离的 staging 工作区准备 Owner、Editor、Viewer 三个账号，并逐项验证：

| 能力 | Owner | Editor | Viewer |
| --- | --- | --- | --- |
| 打开项目、历史图片和视频 | 允许 | 允许 | 允许 |
| 编辑画布、提交生成和润色 | 允许 | 允许 | 拒绝 |
| 管理项目成员、删除项目、读取项目审计 | 允许 | 拒绝 | 拒绝 |
| 管理工作区成员、共享素材、工作区审计 | 允许 | 拒绝 | 拒绝 |

同时覆盖刷新、重新登录、浏览器断开后任务完成、旧项目加载和跨设备同步。测试生成链路时使用独立测试项目与非敏感提示词。

## 2. 安全事件与告警

Railway API 日志中的结构化事件应进入集中日志或 Sentry：

- `security.rate_limited`：同一用户或来源持续触发时告警。
- `security.mfa_required`：用于确认 Owner 敏感操作是否被正确拦截。
- HTTP 401/403 激增：排查令牌过期、Origin 配置或越权尝试。
- HTTP 5xx、Worker stalled、任务中断：排查数据库、Redis、Provider 或回填链路。

建议初始阈值：5 分钟内同一主体超过 20 次限流，或 API 5xx 比例连续 5 分钟超过 2% 时通知维护者。阈值应按真实流量调整。

## 3. 审计日志

Owner 可从账户菜单的“安全日志”读取最近记录。服务端 `GET /api/audit` 是权威来源；客户端只负责筛选和展示，不修改记录。重点保留成员权限、项目删除、账户安全和生成任务事件的 `actorId`、`projectId`、`targetId`、`requestId` 与时间。

## 4. 备份与恢复演练

1. PostgreSQL 使用托管平台的自动备份或定时快照；对象存储开启版本保护或生命周期策略。
2. Redis 仅是调度状态，不作为任务与媒体的唯一备份来源。
3. 每月至少一次把最新备份恢复到隔离环境，不连接生产 Worker 和真实 Provider。
4. 验证用户、项目、项目成员、画布图谱、Yjs 更新、任务、输出、媒体对象和审计记录数量。
5. 随机打开历史项目，确认图片、视频和已完成任务能够重新回填。
6. 记录恢复点、耗时、缺失项和修复动作；演练结束后销毁隔离凭据与临时数据。

初始目标建议：RPO 不超过 24 小时，RTO 不超过 4 小时；正式商用后按业务承诺收紧。

## 5. 发布门禁

Pull Request 自动执行测试、架构边界、凭据扫描、生产构建和生产依赖审计。发布前还需人工确认 Railway/Vercel 环境变量、CORS/Origin、MFA 开关、健康检查及一次历史项目恢复。

## 6. 测试账号

隔离验收可以用两个 workspace `member`（不要 Owner）。身份必须同时写入 Supabase Auth 与 Railway `app_users` / `auth_identities`；只建 Auth 用户无法进入工作台。Auth `user_metadata.test_account` 标成测试号。口令只放密码管理器，不写仓库、不写文档、不进工单正文。验收结束后停用成员并 ban 对应 Auth 用户。需要测 Viewer 时，把测试号加进项目并设项目角色，不另开一套账号。

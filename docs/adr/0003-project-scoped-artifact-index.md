# Artifact Index 使用项目级复合身份并保留历史记录

Artifact ID 由多种旧客户端、工具与生成任务产生，`legacy-writeback` 等旧 ID 可能跨项目重复，因此索引选择 `(project_id, artifact_id)` 作为身份，而不要求全局唯一。Artifact Index 是历史血缘目录，画布节点或素材引用删除后不级联删除 Artifact；这避免“整理画布”等 UI 操作破坏审计、恢复与后续 Agent 检索，但意味着媒体实体的实际可用性仍须单独校验。

Agent 结果区以服务端 Artifact Index 为历史权威读模型，并合并当前画布中尚未完成索引写入的新产物。索引请求失败或旧环境尚未迁移时，界面回退到原有项目读模型，不阻断生成与结果查看；普通非 Agent 生成记录不会进入 Agent 结果区。

迁移在同一事务内对 Agent 消息、行动回执与生成任务三类旧来源执行缺失对账，并验证索引 payload 的 ID、类型与来源一致性。任何应回填记录缺失或 payload 损坏都会抛出异常并回滚；索引中额外存在的历史记录被视为合法保留。

# O5 工具搜索评测（2026-09-22）

## 调用前冻结的方案

用户要求“评测工具搜索”。本轮只测试 `this-that-model-1.0` 是否能从工具目录中保留完成任务所需的能力，不是检索历史调用日志。只发送新编合成任务和虚构工具描述，不发送真实项目内容、私有 Prompt、生产工具描述、会话、媒体或凭据正文。不调用真实工具、主模型、Jev 或生图，不改生产，不提交或发布。沿用已有 FLock 合成评测授权，密钥仅从不回显 stdin 临时传入。

### 数据与协议

- 8 个虚构工具：画布搜索、历史产物搜索、已保存规则读取、生成任务状态、保存计划、生图、删除画布节点、澄清用户意图。能力边界和参数在 fixture 中人工定义，不声称等同于生产工具目录。
- 24 个中文合成场景：8 开发、16 留出，每题对全部 8 个工具独立分类，最多 **192 次**请求。题目是不同内容场景，任务类型在开发和留出之间共享；不是未知领域泛化测试。单题内的 8 对不是 8 个独立用户任务。
- 固定一版判据、温度 1、三类完整概率，不调阈值，不按留出结果改题重跑。Gold 为调用前编写的必要能力集合，另标信息不足；未经独立人工裁决。
- “需要”指完成本次明确请求的一步，可多选；同任务前序工具能提供缺失标识时，不排除后序工具。关键意图或必要生成参数需用户补充时，先澄清，依赖补充的工具记信息不足。没有合适工具但请求明确时不强行调用或追问。
- 分类结果不是执行授权，不能代替参数校验、确认、幂等和恢复。参数正确性、执行顺序、实际成功率均未测。

### 比较与指标

1. 当前完整已注册目录作为**可用能力基线**：不丢工具，但不能把工具存在当成主模型选对，主模型选择准确率未知。当前实现见 `server/agent/tools/agentToolRuntime.mjs:113` 和 `server/agent/turn/botanicAgentTurn.mjs:547`。
2. 实验关键词 Top-3：请求及显式状态与合成工具描述的文字二元组重合数排序，哈希打破平局。不声称这是当前生产工具搜索；它没有同义词、语义索引或查询改写。固定前三个无法覆盖四步任务，此上限会单独说明。
3. 分类器建议：对全部 8 个工具逐个判断，取 argmax 为“需要”的集合。不会把目录回退算进分类器成绩。
4. 保守回退：任一“信息不足”、无“需要”或未完成时，恢复原有完整授权目录。回退只保住能力，不代表工具执行，也不保证主模型一定正确选择。否则保留分类器建议。

分别统计必要工具微平均召回、建议精确率、正例任务全部必要工具覆盖、精确集合、无工具任务的误选、只读任务误建议写入/生图/删除。将“不必要但相关”也计为多选，不预先放宽标签。

工具 schema 缩减采用现有 `estimateAgentContextTokens` 对虚构 OpenAI 格式 schema 估算；没有复现完整生产 `why`/工具包装，不是实际主模型用量。分类调用 usage 与主模型省下的估算 token 分开列示，不合算为费用收益。实际串行每题 8 次的合计耗时是新增分类成本，完整 Agent 端到端耗时未知；不从单请求延迟推断用户操作提速。

### 停止与最低信号

- 最多 192 次分类及一次模型报价查询；25 秒请求超时，网络/协议错误即停，不自动重试可能已计费请求。
- 出网前排他预留全新结果文件；结果冻结数据、请求和相关实现 SHA-256，保存全部合成题、输出概率、分题结果和费用头。
- 继续考虑工具裁剪的最低信号：留出必要工具召回 100%、无只读任务危险建议、无“无需工具”误选。不是上线验收，小样本即使全过也须另测真实分布和主模型端到端效果。
- 不因生成完整目录回退而宣布分类器达标；实际账单缺失时不把未返回费用当免费。

## 实测结果

**结论：本轮“逐工具三分类 + 保守回退”未达到预先设定的必要工具召回门槛，不建议接入生产工具裁剪。** 不是少量误选，而是大量“信息不足”导致漏选；开启原先固定的回退后，所有留出任务都恢复完整目录，没有获得目录压缩收益。

2026-09-22 11:33–11:34（Asia/Shanghai）完成 192/192 次真实 FLock 分类，无重试、无协议错误，返回模型标识 `this-that-model-1.0`，权重 revision 未提供。主结果采用 16 个留出任务、128 个请求/工具对；开发集不用于选提示词或阈值。

完整目录提供 100% **能力可用性**，不代表主模型正确选择或成功完成任务。关键词 Top-3 是弱实验对照，不是现有生产 Agent；其固定容量本来就装不下四步任务，不能据此比较模型的全部能力。表中回退目录的多余工具也不能当成模型主动提出执行，更不能记为越权执行。

分类器建议精确率 100% 的分母只有 8 个，不能掩盖必要工具召回只有 42.1%。精确集合 9/16 包含 3 个无需工具任务，不等于 9 个实际多步任务已完成。

### 错误在哪里

- **不相关被混成了信息不足。** 106 个本应“不需要”的工具对，有 54 个被判“信息不足”。真正的信息不足只有 3 对，模型共报了 67 对。因此任何不确定即回退的既定策略，在 13 个任务上被触发；另外 3 个无需工具任务按既定空集策略回退，合计 **16/16 全量回退**。
- **明确的必要工具也漏掉。** 19 个必要工具中，10 个被判信息不足，1 个被判不需要，只认出 8 个。总三分类准确率为 **63/128（49.2%）**，macro-F1 **0.4441**；开发集准确率 28/64（43.8%），必要工具召回 7/9（77.8%），不能拿开发结果替代留出结果。
- **多步能力选择不可靠。** “读禁用颜色，再保存方案”(`h9`) 两个必要工具都未选，其中 `plan_build` 明确判“不需要”；“查找过期节点后删除、保留历史”(`h10`) 两个工具都未选；四步任务 (`h16`) 只选出读规则，漏了查参考、保存计划和生图。相对地，“查参考后生成”(`h8`) 两个工具均选对，说明不是所有多步任务都失败。
- **单步也存在遗漏。** “定位当前工作区文字卡片”(`h1`) 的画布查询、读取已保存材质限制 (`h3`) 的规则读取都被判为信息不足。缺生成参数 (`h14`) 时，连明确需要的澄清工具也未选中。
- **概率分数不是正确率保证。** 留出 score≥0.95 的 56 对中错了 24 对；不要把返回分数直接作为校准置信度，也不能指望简单提高阈值补回这些漏选。

本轮没有观察到只读任务被主动建议写操作，3 个无需工具任务的建议也都正确为空。但这只是本样本的正面结果，不构成提示注入、权限或真实执行安全验证。

### 速度、上下文与费用

- 单次分类客户端 p50 **249.70ms**、p95 **271.06ms**；逐题 8 次串行分类合计 p50 **2,007.94ms**、p95 **2,463.18ms**。这是网络+响应+解析新增耗时，未包含主模型与工具执行。
- 原合成完整目录估算每题 **1,020 token**。16 个留出任务原为 **16,320** 估算 schema token；回退后仍是 **16,320**，没有节省。若忽略回退只拿主动建议，看起来能降至 1,126，但代价是丢掉 11/19 必需能力，不能宣称有效优化。
- 分类接口实际报告全轮输入 **42,104 token**、输出 **0**；其中留出输入 **28,552 token**，平均每题 1,784.5。这是新增分类调用用量，不能和估算主模型 token 混算费用或速度收益。
- 模型报价端点本次仍返回输入/输出每 token 为 0，但每请求单价缺失，192 个响应没有费用头，实际账单未核对。因此不能宣布免费或得出已验证的成本节省。
- 未运行主模型对照，**端到端速度、参数有效率、执行顺序与任务成功率未知**。本轮只能说前置筛选增加约 2 秒且在既定回退策略下没有缩短工具目录，不能宣布生产整体速度变化的精确数值。

### 决策与后续方向

当前不接生产，不用本轮分类结果隐藏必要工具。固定三分类把“语义是否相关”“是否为本任务必要步骤”“参数现在是否足够”放到一个判断里，可能增加了难度；这是根据错误分布提出的**待验证假设**，不是已证明的模型内部原因。

若继续研究，优先做更窄的新实验：模型只回答“用户明确请求是否涉及这项能力”，先作为排序提示而不是删工具；关键状态、工具是否可用和执行权限仍由代码处理，主模型负责计划、参数与次序。新的二分类/分阶段方案须使用新留出题，不能把本轮错题改好后作为提升证据。也不要通过删除“信息不足”选项来虚构确定性：改变选项后必须重新量测漏选和误选。

生产当前应保留原注册工具与冻结能力快照；小目录不建议增加逐工具外部请求。若以后工具数量明显增长，再评估本地目录检索、按需加载和不会静默丢失能力的兜底入口，并与主模型完整目录做实际端到端比较。本轮未实施这些改动。

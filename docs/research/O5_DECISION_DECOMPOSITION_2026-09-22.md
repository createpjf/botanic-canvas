# O5：把总分类拆成独立判断（2026-09-22）

范围：只增加合成离线实验，不接入正式路由，不修改 Ontology、权限、模型配置、生成或恢复逻辑。第一轮六分类数据、请求和结果原样保留。

## 1. 拆成哪些问题

这些是职责边界，不是每轮必须调用五次模型的新流水线。复用现有实体和工具；代码能直接判断的，不调用分类模型。

| 问题 | 需要的事实 | 由谁负责 | 输出与边界 |
| --- | --- | --- | --- |
| 用户想做什么？ | 当前请求、必要上文、明确引用 | 现有解析/Planner；暂不替换 | 对话、改提示词、检索、生成、修改对象等语义；允许复杂、多意图请求继续交给 Planner |
| 想查哪个来源？ | 请求、指代对象的最小上下文 | **本轮唯一的分类实验** | 当前画布、历史 Artifact、已保存规则，或交回 Planner；只是来源建议 |
| 条件是否满足？ | 引用是否解析、图片是否存在、读取器是否可用、待确认计划是否唯一 | 确定性代码 | 缺目标、缺计划、来源不可用等具体原因；不改写已经明确的意图 |
| 是否允许执行？ | 当前用户/项目权限、绑定的提案与版本、确认状态、配额 | 现有服务端治理 | 不由分类概率、对话措辞或 UI 状态授予权限 |
| 执行到哪、能否恢复？ | Turn/Checkpoint、Run/Job、Action Receipt | 现有运行时 | 不重建第二套状态机，不因恢复而重新分类、改变已冻结决策或重复派发 |

依据：`docs/PRODUCT_ARCHITECTURE.md` 第 3–5 节已经定义这些实体与权威来源；`docs/ARCHITECTURE.md` 的 Agent Turn Runtime 章节要求从固定步骤恢复；ADR 0003 区分历史 Artifact 与当前画布，整理画布不删除历史。

关键例子：

- “把这张图改成夜景”：无论有没有选图，语义都是生成/编辑；没图是 `missing_target`，不是意图 `unknown`。在本轮检索题里两种情况都为 `defer`，因为它不是检索请求。
- “找昨天生成的标志”：语义来源始终为 `artifacts`；即使历史读取器不可用，也不改标成 `defer`。程序另返回 `unavailable_source`，不能擅自换到画布或外网。
- “确认”：有待确认计划也不代表分类器可以执行；仍需绑定对象、版本和权威确认。没有计划则澄清。两种情况均不进入本轮检索路径。

## 2. 检索来源小题

固定四项：

| 稳定标识 | 描述性选项含义 | 将来接入时复用的既有入口（本轮不调用） |
| --- | --- | --- |
| `canvas` | 当前画布节点、选择、布局 | `server/agent/tools/botanicAgentOperationalTools.mjs` 的 `canvas_query` |
| `artifacts` | 已生成结果、历史记录及血缘 | 同文件的 `artifact_search` |
| `rules` | 已保存品牌规则或设计偏好 | `server/agent/tools/botanicAgentContextTools.mjs` 的 `project_memory_search`；不等同于全部 Brand Kit 文档读取 |
| `defer` | 非检索、多来源或不能明确归入上述单一来源 | 交回现有 Planner，不等于拒绝用户请求 |

题目问“指向哪个来源”，不问“是否获准执行”。`defer` 是模型可选的语义结果；`low_confidence`、`missing_score`、`unavailable_source` 是包装层独立的回退原因，不能统称为 unknown。

State 只取合成的 `request`、`context`、`availableSources`；边界样本另外提供 `selectedImageCount` 或 `pendingPlanCount`。后两项用于验证非检索请求不会因为“有图/有计划”就变成检索请求。gold、类别、前置条件标注、实体 ID、媒体地址、项目文件、真实消息及授权凭据不进入请求体。

上下文文本只是指代材料，不升级为指令。`availableSources` 将来必须由服务端读取能力与权限过滤结果提供，不能相信请求中的自报值。本轮是固定合成事实，不读取生产环境。为隔离选项表达的效果，实验固定四选项并由程序另挡不可用来源；尚未测试动态候选集，不能把固定词表阈值直接迁移过去。

外网搜索不在候选中；同一句需要同时查画布和历史时交回 Planner，不假装四选一能够完成多步任务。如果权威引用已唯一确定目标来源，直接用现有代码即可，不需新增模型调用。

## 3. 离线实验：一次只改变一个因素

入口：`scripts/evalAgentDecisionO5.mjs --retrieval`；数据：`scripts/fixtures/agentRetrievalO5.mjs`。

- 新集共 48 条：12 个场景族 × 中/英文 × 两种状态；dev/holdout 各 6 族、24 条。同一族及其中英表达、状态对不会跨 split。全部为 agent 编写的合成 gold，未经人工独立复核，不代表真实流量。
- 状态对既有“应该改变答案”的指代切换，也有“不应改变语义答案”的权限/能力可用性变化、否定、注入式备注、缺图、裸确认。
- 四种开发集版本：`described-json`（基准）、`bare-json`（仅换选项描述）、`described-prose`（仅换相同事实的序列化）、`no-state-json`（仅移除状态，作为诊断对照）。所有版本的题目、选项顺序、temperature、模型和最大输出预算保持相同；bare 版本只改变 enum 文本。
- 每版先测 24 条 dev，共 96 次；在前三个完整 dev 版本中选择最佳版本与阈值。无状态对照不参加准入选择。**先锁定选择，再只测该版本的 24 条新 holdout**，合计最多 120 次。失败即停止，不自动重试；不足完整 dev 不进入 holdout。
- 阈值从 0.00–1.01 按 0.01 步长选择，目标为 dev 上包装层后的四类 macro-F1；并列优先低阈值，再按上述版本顺序。不是概率校准，也不是生产安全阈值。不复用第一轮 0.49。
- 原始指标按来源语义 gold 计算；包装层指标把弃权保留为原类别的 FN。另报 `routeOutcomeAccuracy`，将来源不可用时正确回退计为正确流程结果，避免把“理解来源”和“具备查询条件”混淆。模型 `defer`、低分、缺分数、来源不可用分别计数。
- 报告同时给出覆盖率、非回退部分正确率、错误来源建议、状态敏感/不敏感对的两条全对数、语言分项、客户端 p50/p95；不能只挑非回退准确率。`unavailableSuggestions` 是防线拦截前的建议数，不是实际越权调用数。
- 固定数据与每个版本请求集合的 SHA-256。留出结果揭晓后不改题目再重测同一留出集；需要迭代时另建新留出族。

默认运行只校验请求形状、输出实验清单，状态为 `prepared_not_evaluated`，不联网、不伪造模型成绩：

```bash
node scripts/evalAgentDecisionO5.mjs --retrieval
node --test scripts/evalAgentDecisionO5.test.mjs
```

已有授权覆盖本轮 FLock 合成对比。远程运行显式加 `--remote`，凭据用既有 `FLOCK_O5_API_KEY` 注入或关闭回显后的 `--key-stdin`；不读取 `.env`，不在命令、代码或结果中保存密钥。仅允许官方 FLock 地址；保留零报价预检、非零费用响应即停、25 秒超时、无自动重试及输出文件不可覆盖的保护。

## 4. 采用条件与未实施部分

拆题并不证明模型有效。即使这 48 条全对，仍需独立人工复核、更多中文及真实分布验证、完整 Planner 的同题/同数据权限对比，以及总延迟和总费用的收益证据。现有本地粗意图启发式不选检索来源，不拿它充当这一窄任务的基线。Jev 是另一个服务，本轮不调用，也不假设 FLock 托管接口具备 Jev 的多问题、Score 或 Noul API。

本轮不新增生产 Feature Flag、数据库字段、Checkpoint 版本或安全策略。若未来获准接入，分类失败和超时回退现有 Planner；所有查询仍走原有项目权限与安全投影。任何可能影响恢复的决策持久化必须单独设计兼容迁移，不能随意把新字段塞入旧 Checkpoint。

# O5 候选匹配离线实验（2026-09-22）

## 调用前冻结的方案

本轮授权来自“候选匹配离线实验”方案后的“开始”。只向 FLock `this-that-model-1.0` 发送新编合成文字；不发送项目记录、真实规则、私有 Prompt、媒体或凭据正文，不调用 Jev、Planner、embedding 或生图，不接生产、不提交或发布。沿用已授权的 FLock 凭据，通过不回显 stdin 临时传入，不落库或写入结果。

### 任务与范围

输入只有中文检索请求、候选来源、候选标题和正文。输出为“匹配 / 不匹配 / 信息不足”，三类完整概率一并保存。匹配只意味着**文字支持检索条件**，不是视觉检查、事实真实性认证或行动授权。已保存规则是在查询某项政策；不同政策不算命中，政策尚未确定则信息不足。模型不能因为检索相关性低就停用已确认规则。

30 个全新场景族，画布/历史产物/规则各 10 个；每族 3 个候选，合计 90 对。12 族开发、18 族留出，同族不跨集，不是把翻译或近重复算作独立场景。每个来源均包含明确条件、否定、同义表达、无合适结果；留出另含资料内伪指令和证据不足场景。旧两轮的测试题不复用。

Gold 是 agent 编写并在调用前按文字判据复核，**未经独立人工裁决**。ID 与初始顺序由不含 gold 的固定哈希产生。三个候选构成受控小池；关键词由 fixture 预先提供，来源也已确定。这不是完整自然语言→选工具→检索的端到端测试，不代表真实生产分布。

### 现有基线与比较对象

| 来源 | 复用当前工作区实现 | 本实验的合成载体 |
| --- | --- | --- |
| 当前画布 | `queryCanvasForAgent` 的 keyword 匹配及 score→ID 排序 | 内存 text 节点；正文经安全查询投影 |
| 历史产物 | `createAgentOperationalReaders().searchArtifacts` 的过滤和已有顺序 | 内存 Store 返回合成时间倒序记录，无真实数据库 |
| 项目规则 | `selectBotanicAgentMemory` 的匹配分档/权重/时效排序 | 人工来源、active、project 范围的合成规则 |

模型只给同一候选池重排：argmax 为 match 的候选按 `P(match)` 前移，其余保留原相对顺序；没有 match 或当题未完成时保持原排序。另记录可选的“首个匹配建议”，但不把保持原列表说成成功拒绝所有结果。保留全体候选，不改任何规则的生效状态（ADR 0006）。未测实际 UI 或执行。

### 预先固定的指标与停止标准

- 一版全中文短判据，内含一个不属于测试场景的对照例；固定温度 1。开发在前、留出在后；本轮不选版本、不搜索阈值、不做概率校准，也不依据留出成绩修改输入再重跑。
- 对存在相关候选的查询，配对比较 top-1、MRR、改善与倒退数；同时统计错误候选前移数。原始三分类另列混淆矩阵、各类 F1、多类 Brier 和高分错误。
- 匹配建议单独报告覆盖率、正确率、正例无建议、无合适结果时的误接受。回退不会抹掉排序错误；无匹配查询不混入正例 top-1 分母。
- Recall@3 是候选池上限检查。同池只调序不会增加召回；受控三候选池得到 100% 不能用来证明生产检索已成功。
- 三次串行分类的客户端合计耗时作为每题模型增量延迟，同时报告现有本地查询耗时。远端模型自身计算耗时、完整 Planner 总耗时未知。
- 记录公开报价与响应费用头；实际账单未经核对时留空。最多 90 次分类请求，另一次模型价格查询；网络/协议失败停止、不自动重试可能已计费请求。结果文件在调用前以排他创建预留，禁止覆盖旧结果。
- **继续验证的最低信号**：留出 top-1 有净提升、没有原本正确的 top-1 倒退、无匹配题不误接受。这只是本轮后续研究筛选，不是上线门槛；延迟/费用的产品容忍值尚未确定。未达到就不建议把当前方案接到该路径。

## 实测结果

**结论：这个窄任务显示排序收益，但未达到预先固定的继续验证最低信号，当前方案不建议接入生产。** 未达到的项是“无合适候选时不误接受”：6 个此类留出场景中误接受 1 个。没有在看到结果后放宽标准、提高阈值、改题或追加调用。

执行时间为 2026-09-22 10:46（Asia/Shanghai）。FLock 返回模型标识 `this-that-model-1.0`，90/90 次完成、无重试、无协议错误；模型权重 revision 未公开。12 个开发场景只作诊断，主结论取一次性执行的 18 个留出场景（54 个请求/候选对）。

| 留出指标 | 原有基线 | 模型判断 + 保留原序兜底 |
| --- | ---: | ---: |
| 有正确候选的查询，正确结果排第一 | 5/12（41.7%） | 12/12（100%） |
| 正确候选的平均倒数排名 MRR | 0.6528 | 1.0000 |
| 原本错误的首位被改善 / 原本正确的首位被破坏 | — | 7 / 0 |
| 三分类准确率 | 不适用：基线没有此三分类器 | 44/54（81.5%），macro-F1 0.8100 |
| 模型主动认出的正确候选 | — | 9/12（75%） |
| 无正确候选的查询被错误建议 | 不定义：基线只给列表，不判断匹配 | 1/6 |
| 给出匹配建议的查询 / 其中建议正确 | — | 10/18 / 9/10 |
| 错误候选被向前移动 | — | 1 个 |

**12/12 不是模型独立答对 12 题。** 其中 3 个历史产物查询被模型判为信息不足，排序保持不动；恰好原始第一条就正确。因此排序 100% 与主动匹配召回 75% 必须一起看。下一批数据若原始顺序不同，兜底未必仍然正确。也未与完整 Planner 阅读候选后的选择比较，不能声称优于现有 Agent 的端到端完成率。

### 错题说明

1. **标题/命名不能代替证据。** `gloss-photo` 要“文字明确说明产品表面无反光”，候选写“文件名：无反光样片；备注：名称为临时命名，实际表面效果未知”。Gold 为信息不足，模型却以 **0.78419** 判匹配，并把它从第二位提到第一位。这是唯一无答案误接受，也是未过预设标准的直接证据。
2. **历史摘要的文字可能没有被充分使用。** `jar-spoon` 的标题已写“量勺卡在罐身侧面的固定扣上”，模型仍以 **0.90012** 判信息不足；`perfume-people` 和 `calm-pool` 也把有文字支持的正例判为信息不足。这三个样本正文均为空、信息全在标题里，但**字段位置导致漏判仍是待验证假设**，不是已确认根因。本轮没有做字段位置对照。
3. **“不相关”与“信息不足”仍会混淆。** 3 条规则题把不同政策判为信息不足，另有一条“材料披露规范未记录”反向判成不匹配。这些错误不等同于越权或错误执行，但表明三分类边界尚未稳定。
4. **高分仍非保证。** 留出 score≥0.95 的 32 对中错 1 对：只写“厚纸装订”的目录候选不能证明有无涂层，应为信息不足，却以 **0.98029** 判不匹配。无答案误接受的分数不是这一高分错误，二者不要混为一例。完整分布已保存，本轮没有利用测试集拟合校准器。

本轮无资料内伪指令导致的 match 误接受，但只有 3 个此类留出场景，不构成提示注入安全验证。

### 时间、成本与证据边界

- 留出每次候选判断客户端 p50 **255.56ms**、p95 **782.91ms**；每题 3 次串行合计 p50 **778.94ms**、p95 **2086.58ms**。这些是网络+服务响应+解析的增量耗时，不是模型裸推理速度，也不是完整 Agent 总耗时。开发集 p95 较高，不能忽略尾延迟。
- 合成内存基线的留出 p50/p95 为 **0.016/0.087ms**，不包含真实数据库、授权读取与生产网络，不应用它计算产品速度倍率。
- 所有 90 次均返回 token usage：输入 **16,892**，输出 **0**。这符合分类接口而非文本生成输出，不能与前轮不同题型的 token 数直接当效率提升。
- `/model/info` 当时返回输入/输出每 token 报价 0；每请求单价没有提供，90 次响应均未提供费用头。报告中 `reportedCostHeaders.count=0,total=0` 意味着**未取得费用头，不是已确认花费为零**；实际账单仍未核对。
- 每题 3 个合成候选、简单属性文字、事先给定来源与关键词，远比真实用户检索窄。Gold 未经独立人工裁决；同一题内的 3 对相关，不能把 54 对当成 54 个独立真实用户任务。12/12 不是可靠性保证。
- 改成候选匹配、中文判据、少量例子、干净输入与新样本同时发生，当前比较只能支持“这一组合在这个小任务有效”，不能分离各项提升的因果，也不能与前两轮来源路由的 F1 直接排名。

### 下一步建议（未实施）

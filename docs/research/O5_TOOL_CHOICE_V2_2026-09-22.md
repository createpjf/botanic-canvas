# O5 工具选择改进 V2：配对实验

## 实测前固定的方案

用户要求“提升在工具调用选择的能力”。沿用合成数据 FLock 评测授权，不发项目内容、真实工具描述、历史消息或媒体，不调用实际工具/主模型/Jev/生图，不接生产或发布。上一轮已经看过的留出题不作新一轮验收题，旧脚本、数据和结果不修改。

### 改动

1. V1 沿用上一轮完整工具描述和“需要/不需要/信息不足”的混合判据。
2. V2 只发请求、已知事实，用短的原子问题询问“本次是否需要某项能力”，输出是/否。能力表固定覆盖同一 8 种合成工具；没有通用授权判定，不询问模型是否可以越过确认。
3. `chooseTools` 仅提供建议及目录排序。非建议项继续保留，权限目录外的名称不能进入结果；缺失/重复结果保留原目录、不伪造选择成功。没有以删除“不确定”选项等同于消除了不确定性。
4. 关键用户输入缺失且已有权威状态说明时，只建议澄清。**此状态在样本中人工给定，不是分类器提取，也尚未接入生产状态来源。** 两臂都应用相同状态规则，并分别报告模型独立、同规则后的成绩和无需该规则的子集。不能把规则增加的正确项说成模型选对。此简化仅覆盖一个整体受阻请求；独立子步骤可先执行的情况未实现，接生产前需另行设计与验证。

### 公平比较与边界

- 24 个新合成任务：8 开发、16 留出；每题 8 个工具，每对都调用 V1/V2，合计 **384 次**。调用顺序按不含 Gold 的哈希交错，减小按时间分组的延迟偏差。失败即停止，不重试；不完整时只比较两臂均完成的对。
- Gold 仍指本轮明确请求必要的工具集合，包含单步、二步、三步、四步、只读否定、无合适能力、缺参和引号内伪指令。场景由 agent 编写，未经独立人工裁决；开发与留出共享领域/任务类型，不是未知领域泛化验证。新题不只是改旧题里的商品名，但无法保证没有任务结构相似性。
- 一版 V2，不在看到留出后改题、选阈值或追加同题尝试。V2 改了问题、选项与描述方式，结果仅可归因于整体方案，不分别声称每项的因果收益。
- 主指标是同题的必要工具召回、精确率、整任务全部必要工具覆盖、精确集合、多余工具、只读危险建议和无工具误选；不拿二分类与三分类的整体准确率直接比较。
- 以客户端单次耗时、每题 8 次串行合计和接口实际 usage 衡量新增开销。没有实际主模型/参数/执行对照，不能宣称 Agent 整体提速或任务成功率提高。V2 保留全部目录，实际 schema 裁剪量固定为 0；假设只暴露建议集的估算缩减不能当已获收益。
- 延续研究最低门槛：留出必要工具召回 100%、只读危险建议为 0、无工具误选为 0。仍非生产准入。模型概率不是已校准准确率；本轮不做阈值调参。
- 25 秒超时，网络/协议错误停止。仅允许新增结果文件；记录请求、数据和实现 SHA-256，旧证据不覆盖。报价/费用头缺失不能解释为免费。

## 结果

**结论：能力选择召回明显提高，但以更多额外建议为代价，仍未达到自动裁剪/执行的研究门槛。** V2 已实现为独立离线建议选择器，没有接入生产；完整授权目录仍保留。不能把此结果写成生产 Agent 已经完成率提高或提速。

2026-09-22 11:47–11:48（Asia/Shanghai）完成 **384/384** 次 FLock 请求，无重试、无协议失败，返回 `this-that-model-1.0`，模型权重 revision 未提供。主结果取相同的 16 个新留出任务，每臂 128 次判断。以下旧版数字是本轮同题重新测得，**不是拿上一轮 42.1% 与新题的分数直接比较**。

### 同题对照：模型独立，不含状态规则补救

| 指标 | V1 混合三分类 | V2 原子能力判断 |
| --- | ---: | ---: |
| 必要工具选中 / 必要工具总数 | 12/21（57.1%） | **20/21（95.2%）** |
| 全部必要工具选齐的正例任务 | 6/13（46.2%） | **12/13（92.3%）** |
| 建议精确率 | 12/12（100%） | 20/24（83.3%） |
| 精确集合，不多不少 | 9/16 | 11/16 |
| 无工具任务被错误建议工具 | 0/3 | **1/3** |
| 只读任务误建议写入、计费或删除 | 0/7 | 0/7 |
| 多余建议 | 0 | 4 |

必要工具召回增加 **38.1 个百分点**，漏选由 9 项降至 1 项。但精确率下降 16.7 个百分点，不能称为所有维度都提升，也不能用 95.2% 表示完整任务执行正确率。没有在看到结果后重新定义多余工具为正确。

### 状态规则的贡献单列

两臂都应用同一个“权威状态已标记缺少用户输入时，先澄清”的规则后：

| 指标 | V1 + 同规则 | V2 + 同规则 |
| --- | ---: | ---: |
| 必要工具召回 | 14/21（66.7%） | 20/21（95.2%） |
| 建议精确率 | 14/14（100%） | 20/23（87.0%） |
| 全部必要工具选齐的正例任务 | 8/13 | 12/13 |
| 精确集合 | 11/16 | 12/16 |

规则为 V1 补回两个澄清工具；V2 原本已经选中这两个澄清工具，因此规则没有补回必要工具，只删除了一项缺主题时的过早生图建议。**这不能算成模型自己修正了生成判断。**

去掉这两个需要人工给定缺参状态的任务后，其余 14 题的模型独立必要工具召回为 **12/19（63.2%）→18/19（94.7%）**。因此本轮改善并不只来自状态规则。规则的状态获取与上游解析准确率仍未评测；单请求整体阻塞规则不能直接迁移到含独立可执行子任务的复杂请求。

开发集 8 题的模型独立召回为 3/8→6/8，精确率 3/4→6/10；同状态规则后召回 4/8→7/8。开发集的多余建议同样存在，不只在留出偶发；本轮没有据此选阈值或版本。

### 哪些任务改善了

- `v2h2`：同时找当前画布和历史产物，旧版只选画布，新版两种都选齐。
- `v2h3`：读材质规则并查排队任务，旧版两个都漏，新版两种都选齐。
- `v2h8`：找历史摘要、读颜色限制、据此生成，旧版只选规则，新版三种都选齐。
- `v2h16`：读规则→找参考→保存计划→生图，旧版缺规则，新版四种都选齐。

这说明在本批合成题中，原子能力判断更容易保留多步骤所需的能力。**它没有生成或验证工具调用次序、参数和输出依赖。** 不能把集合完整当作计划正确或任务执行成功。

### 剩余错误

1. **漏掉隐含的前置读取。** `v2h1` 要比较两张当前画布卡片的说明，实际必须先读取节点；V2 却把画布搜索/定位判为不需要，分数 0.7011。能力短描述偏“查找/定位”，没强调“为比较读取内容”，是下一轮可验证的解释，不是已确认的单一根因。
2. **已有参数仍多读规则。** `v2h7` 直接生图且参数已定，额外选了 `rule_read`（0.6204）。此合成任务未要求项目规则读取，不改 Gold 为其开脱。
3. **已知 ID 仍多查一次。** `v2h10` 已给节点 N-932，只需要删除，却额外选了 `canvas_find`，分数高达 **0.9977**。高分不保证选择必要，单纯提高阈值也不能修复这条。
4. **不支持的操作选了相近工具。** `v2h11` 要取消任务，并明确不要以查询冒充取消，但目录没有取消工具；V2 仍建议 `job_status`（0.7036）。这导致预设的无工具误选门槛失败。
5. **缺参数仍建议生成。** `v2h14` 没有主题时同时选澄清和生成（生成分数 0.5228）；已知缺参规则在建议层去掉生图，但没有测试任何真实执行权限。

本轮只实现并保留建议排序，不删未选工具，不执行上述建议。未因错误无实际副作用就把它们计为正确。

### 效率与费用

| 留出指标 | V1 | V2 |
| --- | ---: | ---: |
| 分类接口实际输入 token | 29,320 | **15,944（减少45.6%）** |
| 单次客户端 p50 | 249.17ms | 247.67ms |
| 每题 8 次串行合计 p50 | 2,001.29ms | 1,985.13ms |
| 每题串行合计 p95 | 3,663.24ms | 2,376.66ms |

提示输入明显减少，但中位数延迟只减少约 **16ms（0.8%）**，仍是每题约 2 秒。16 个任务不足以认定尾延迟改善稳定，不能把一次 p95 差距全归因于提示词缩短。没有实现并发、缓存、少调用分支或主模型加速，不估算未测速度收益。

两臂加开发集总输入 **66,720 token**、输出 0，384 次都报告 usage。报价接口返回输入/输出每 token 为 0，每请求单价缺失，全部响应没有费用头，实际账单未知；token 减少不等于已经确认节费。

选择器保留全部工具，所以**实际目录缩减为 0**。复用计分器内的 `schemaReductionEstimate` 仅表示假如单独暴露建议集的估算，不是本次实现获得的压缩收益。端到端耗时、主模型参数有效率和工具执行成功率均未知。

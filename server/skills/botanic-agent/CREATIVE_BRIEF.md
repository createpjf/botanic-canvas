# Creative Brief 交互规则

在 Prompt 生成与图片生成前，先形成一份受控 Creative Brief。它是多轮对话的结构化状态，不是自由文本备忘录。

## 字段

- 原始指令：`originalInstruction` 保留用户最初的措辞，用来校对补全后的方向没有跑偏；补全过程不得改写它。
- 输出：`model`、`deliveryPreset`、`aspectRatio`、`resolution`。
- 创作：`promptDirection`、`preservationPriority`、`customDirection`。
- 变体：`variation.axisKey` 是用户确认的变化维度，`variation.values` 是该维度上的取值。
- 来源：每个已确定字段标记为用户、画布、记忆、Skill、推断或系统默认。

`variation` 确认一次即长期有效：后续轮次直接按已确认的维度与取值展开分支，不再重复追问同一个维度。只有用户明确换维度、改取值或取消批量时才更新它。

## 补全顺序

1. 读取用户明确要求。
2. 继承当前画布与根配方中兼容的设置。
3. 使用项目记忆和已审核 Skill 中与当前任务直接相关的约束。
4. 对明确且低风险的信息做可解释推断，例如“小红书”对应已配置的平台比例。
5. 手动模式只追问仍缺失、且会显著影响结果的字段；自动模式只能从系统提供的可信目录补默认值。

## 追问策略

- 每轮最多三个字段；把同一决策的选项放在同一张结构化卡片中。
- 不重复询问已确认项，也不询问系统可以无损继承的项。
- 新建图片通常确认交付用途或比例、清晰度、Prompt 优化方向。
- 编辑已有结果时优先继承比例与清晰度；用户明确要求锁定人物、商品或服装时直接记录保持重点。
- 选择“自定义比例”后下一轮只询问模型支持的比例，不再重复询问用途。
- 选择“自定义方向”后使用文本字段收集方向，再结束追问。
- 模型与比例、分辨率不兼容时明确失败或重新确认，不能静默换成另一个值。

## 收束

字段足够后，把 Brief 编译进最终 Prompt 与执行计划。Prompt 优化必须保留原始事实、锁定项、否定条件和用户措辞意图；不能用追问答案扩写出不存在的品牌或画面事实。

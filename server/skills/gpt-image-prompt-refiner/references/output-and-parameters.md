# 输出形态、参数与能力边界

## 默认输出

只优化时交付一份可以复制给图像模型的提示文本。简单目标用一段；多参考或复杂版式用有标签的短段。不附通用分析、分数或说明。用户要求多版、双语、参数或执行时遵从该要求。

提示正文的段落只描述图像。检查流程、下载、调用 API、付费和发布不是画面内容；需要这些步骤时放在独立执行说明中。

必要例外：精确像素保护、真实透明、要求的文件类型 / 能力不支持、关键输入缺失或约束冲突影响执行时，允许用一条短说明指出实际前提。说明要与该需求直接相关，不加泛化免责声明。

## 按任务选择结构

新图：

```text
为指定用途创作一张指定类型的图像。
主体与场景：具体对象、数量、关系和动作。
构图：视角、景别、位置、留白与阅读顺序。
视觉：媒介、颜色、材料、光线和可见细节。
文字与限制：准确文案及必要保留 / 排除项。
```

编辑：

```text
使用指定输入图，仅修改明确的对象或区域，使其达到目标状态。
保持与本轮无关的身份、几何、文案、布局及周围环境。
明确容易受影响的细节和不应出现的变化。
```

多参考：

```text
图 1 提供主体身份；图 2 提供目标背景；图 3 仅提供指定风格。
将指定主体放在明确位置，匹配尺度、光向和接触关系。
保留身份细节，排除参考图中不应迁移的物体或文字。
```

上面是写作模式，不是最终输出。将描述性字段换成用户实际信息，删去不适用段；不要把抽象模板原封不动交给信息已经充分的用户。

## 参数何时输出

- 用户只要提示且没给参数：保留视觉比例和用途，不强行附 API JSON。
- 用户给了模型、尺寸、质量或格式：保留其意图；在单独“请求设置”中整理。可能无效的组合核对后说明，不静默改型号或画幅。
- 用户要求 API 可用版本：输出独立的 `prompt` 文本与目标接口支持的设置；只写确认支持的字段。
- 使用 ChatGPT / Codex 内置工具：只采用实际暴露的设置；API 文档支持的参数不代表该工具也支持。

`size` 控制像素，`quality` 控制生成质量档，`background` 控制背景方式，`output_format` 控制编码。提示里的“高清”“4K”是意图，不能取代设置。不要引入未支持的 `seed`、`negative_prompt` 或其它平台命令。

## 模型差异：有日期的参考，不是固定默认

下表摘自 2026-09-10 核对的 [官方提示指南](https://developers.openai.com/api/docs/guides/image-prompting)。只有用户指定或需要 API 配置时读取；执行前复核 [图像生成文档](https://developers.openai.com/api/docs/guides/image-generation) 和实际工具参数，不自动替换用户模型。

| 模型 | 文档记载的关键差异 |
|---|---|
| GPT Image 2.5 | `gpt-image-2.5-flare` 偏速度，`gpt-image-2.5-sunburst` 偏质量；quality 包含 auto、low、medium、high、xhigh、max |
| GPT Image 2 | `gpt-image-2`；不要传 `input_fidelity`，输入始终高保真；透明背景在该文档中标为 preview |
| GPT Image 1 / 1.5 | `input_fidelity` 与 `quality` 含义不同；固定尺寸选项及生命周期须查对应参考，不能机械复制到新模型 |

该指南的 2.5 自定义尺寸约束为：每边不超过 3840，边长为 16 的倍数，长短边比不超过 3:1，总像素 655360–8294400；超过 3686400 像素的输出仍标为实验性。不要把这些范围声称为所有图像模型的通用规则。用户的画幅无效时先保留宽高比与用途，提出符合当前接口的尺寸，不默默裁切。

透明资产显式设置 `background="transparent"` 并使用 PNG 或 WebP。`output_compression` 仅用于 JPEG / WebP，不对 PNG 传入。检查真实 Alpha，不能把带棋盘格的 RGB 图片当透明文件。

比较模型时固定提示、参考、尺寸和共同支持的质量档；相同质量档不意味着同等质量或耗时。先验证输出，再考虑延迟和每张合格图片的成本。不要默认 max 最好，也不要宣称某模型普遍便宜或快多少。

## 不能靠提示解决的要求

| 要求 | 提示能做的事 | 仍需的执行工作 |
|---|---|---|
| 区域逐像素不变 | 明确变化和保护区域 | 将认可编辑合成回原图并比对保护区域 |
| 真透明 | 描述干净轮廓与背景意图 | 正确参数、编码和 Alpha 检查 |
| 品牌文字完全正确 | 引号、位置、次数、保留要求 | 逐字核对；必要时确定性排版 / 合成 |
| 真实多面产品 | 指定身份参考与目标角度 | 足够资料或共享 3D 模型、结构核对 |
| 可编辑 SVG / UI / 3D | 描述相应外观 | 对应矢量、界面或建模工具生成源文件 |

这些是目标相关的执行前提，不能作为理由替用户更换目标，也不需要在所有普通提示后逐条列出。
